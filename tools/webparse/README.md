# webparse — парсер вебсторінок у читабельний текст і DOCX

Бере вебсторінку (статтю, новину, довідку, сторінку журналу) і залишає з неї лише основний вміст:
заголовки, абзаци, списки, **таблиці**, **рисунки й графіки** з підписами. Меню, рекламу, банери
cookie, кнопки «поділитися», коментарі й підвал сайту прибирає. Результат можна переглянути у
вебінтерфейсі й завантажити як **DOCX** (документ Microsoft Word, відкривається також у LibreOffice
та Google Docs).

Адреси можна вставити вручну або **завантажити файлом зі списком посилань**: .txt, .csv, .md,
.docx, .xlsx, .html, .pdf. Парсер сам знайде в ньому всі адреси `http(s)://…`, прибере повтори
й обробить кожну сторінку.

## Встановлення

Потрібен Python 3.10 або новіший.

```bash
cd tools/webparse
pip install -r requirements.txt
```

Для динамічних сайтів і графіків, які малює JavaScript, потрібен ще Playwright (бібліотека, що
керує справжнім браузером Chromium). Його встановлювати необов'язково:

```bash
pip install playwright
```

```bash
playwright install chromium
```

## Вебінтерфейс

```bash
python3 app.py
```

Відкрийте http://127.0.0.1:8000.

1. Вкладка **«Адреси сторінок»**: вставте одну чи кілька адрес. Можна вставити й цілий список
   літератури, посилання з нього парсер знайде сам. Вкладка **«Файл із посиланнями»**: оберіть або
   перетягніть файл.
2. Параметри:
   - **Рисунки й графіки** — завантажувати зображення й SVG-діаграми (SVG — векторний формат рисунків);
   - **Рендеринг JavaScript** — відкривати сторінку в браузері. Потрібен для сайтів, що будують
     вміст скриптами, і для графіків на `<canvas>` (Chart.js, Highcharts, Plotly, ECharts,
     вбудовані Datawrapper/Flourish). Такі графіки зберігаються як знімки. Працює повільніше.
3. **Обробити**. Ліворуч з'явиться список сторінок зі статистикою (слова, таблиці, рисунки),
   праворуч — текст обраної сторінки в читабельному вигляді.
4. Завантаження:
   - **DOCX цієї сторінки** — одна сторінка;
   - **Усе одним DOCX** — збірка: титул зі змістом, кожне джерело з нової сторінки, наприкінці
     список адрес, які не вдалося обробити;
   - **Окремими файлами (ZIP)** — окремий DOCX на кожну сторінку в одному архіві.

## Командний рядок

```bash
python3 -m webparse https://example.org/article
```

```bash
python3 -m webparse -f посилання.docx -o збірка.docx --title "Матеріали до теми 3"
```

```bash
python3 -m webparse -f посилання.txt --separate out/
```

```bash
python3 -m webparse https://example.org/dashboard --render
```

```bash
python3 -m webparse https://example.org/article --text
```

Перший приклад зберігає одну сторінку в DOCX. Другий робить збірку з файлу посилань, третій — окремі
DOCX у теці `out/`, четвертий — рендеринг JavaScript (графіки на canvas). П'ятий лише виводить
текст у термінал.

## Що потрапляє в DOCX

- назва, джерело (активне посилання), автор і дата публікації (з метаданих сторінки), дата звернення;
- заголовки з правильною ієрархією (h2 → «Заголовок 1» тощо), тож у Word працює автоматичний зміст;
- абзаци з жирним, курсивом, верхнім/нижнім індексом (CO₂, C₄) і активними посиланнями;
- нумеровані й марковані списки, зокрема вкладені;
- таблиці з об'єднаними клітинками (colspan/rowspan), виділеним рядком-заголовком, який повторюється
  на кожній сторінці, і підписом «Таблиця N»;
- рисунки й графіки за шириною сторінки з підписом «Рис. N» і посиланням на файл-джерело.
  WebP, GIF і SVG автоматично перетворюються на PNG. Для мініатюр, що ведуть на велике зображення,
  береться велике;
- код і формули (MathML — текстом), цитати;
- бібліографічний запис сторінки за APA 7 («Як цитувати»).

Шрифт — Times New Roman 12, поля 2,5 / 1,5 / 2 / 2 см.

## Як парсер знаходить основний текст

1. Прибирає скрипти, стилі, приховані елементи, меню (`<nav>`), шапку й підвал сайту, бічні панелі,
   блоки з класами на кшталт `cookie`, `share`, `comments`, `related`, `advert`.
2. Шукає контейнер статті: `<article>`, `<main>`, `[itemprop=articleBody]`, відомі класи WordPress,
   Вікіпедії та видавців. Якщо їх немає, оцінює абзаци так само, як режим читання в браузерах
   (Readability). Довгі абзаци з комами додають бали своєму контейнеру, а багато посилань знімає бали.
3. Таблиці для верстки (вкладені таблиці, одна колонка) розгортаються в звичайний текст. Справжні
   таблиці даних лишаються таблицями.
4. Відкидає піктограми, логотипи, лічильники-«пікселі» й зображення, менші за 40 px.

## Застереження

- **Джерела.** Якщо сторінка російська, білоруська або російськомовна (домен .ru/.by, `lang="ru"`,
  характерні літери), парсер попереджає: за правилами сайту кафедри такі джерела не використовуються.
- **Ліцензії.** Рисунки в DOCX мають посилання на джерело, але ліцензію парсер не перевіряє. На сайт
  кафедри можна брати лише фото з відкритою ліцензією (CC BY, CC BY-SA, CC0, суспільне надбання).
- **Сторінки за входом і PDF** парсер не обробляє. Для PDF-файлу він повідомить, що це не вебсторінка.
- **Безпека.** Вебінтерфейс типово доступний лише на цьому комп'ютері (127.0.0.1). З параметром
  `--host 0.0.0.0` його побачить уся локальна мережа, і будь-хто в ній зможе змусити сервер
  завантажувати адреси, зокрема внутрішні. Не відкривайте його в інтернет.
- Чому це не сторінка на самому сайті кафедри: сайт статичний (GitHub Pages), а браузер не дає
  сторінці одного сайту читати чужі сайти. Це обмеження CORS (Cross-Origin Resource Sharing,
  політика спільного доступу між доменами). Тому парсер працює як окрема програма.

## Тести

Тестам мережа не потрібна: вони піднімають локальну сторінку з меню, банером cookie, таблицею з
об'єднаними клітинками, SVG- і canvas-графіками, «лінивим» WebP-зображенням і сторінкою у
windows-1251.

```bash
python3 -m pytest tests -q
```

Тестову сторінку можна відкрити й вручну: `python3 tests/serve.py` → http://127.0.0.1:8765/article.

## Будова

```
app.py                  — вебінтерфейс (Flask): завдання у фоні, перегляд, DOCX / ZIP
templates/index.html    — сторінка інтерфейсу
webparse/fetch.py       — завантаження сторінок (кодування) і зображень (→ PNG/JPEG)
webparse/extract.py     — HTML → блоки: очищення, пошук основного вмісту, таблиці, рисунки
webparse/render.py      — необов'язковий рендеринг у Chromium (Playwright), знімки графіків
webparse/pipeline.py    — повний цикл для однієї чи багатьох адрес (паралельно)
webparse/docx_out.py    — блоки → DOCX (python-docx)
webparse/preview.py     — блоки → HTML для перегляду
webparse/links.py       — адреси з файлів (.txt, .csv, .docx, .xlsx, .html, .pdf)
webparse/__main__.py    — командний рядок
tests/                  — тести й локальна тестова сторінка
```
